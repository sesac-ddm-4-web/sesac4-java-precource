# 심화 과제: 콘솔 계좌 관리 (선택, C트랙 권장)

예상 2.5시간 · 시작 파일 없음 (빈 파일부터 직접 만듭니다: `src/extra/Bank.java` 권장)

숫자 야구가 "로직"을 만드는 과제였다면, 이 과제는 "도메인"을 만드는 과제입니다. 계좌라는 개념을 클래스로 설계하고, 잘못된 요청을 거절하고, 상태를 관리합니다. 백엔드 개발의 축소판이라고 생각하면 됩니다.

이 과제에는 특별한 규칙이 하나 있습니다. AI를 얼마든지 써도 됩니다. 통째로 생성시켜도 됩니다. 대신 결과물을 검증하고 설명하는 책임은 전부 여러분에게 있습니다. 입과 후 배우게 될 "AI 산출물 검증"의 예습입니다.

## 요구사항

**Account 클래스**

- 필드: 계좌번호(String), 소유자 이름(String), 잔액(long)
- 생성자로 세 값을 받아 초기화

**메뉴 반복 (콘솔)**

```
===== 계좌 관리 =====
1. 계좌 생성  2. 입금  3. 출금  4. 조회  5. 전체 목록  0. 종료
선택:
```

- 계좌는 배열로 관리합니다. (예: `Account[] accounts = new Account[100];` 와 현재 개수 변수)
- 각 메뉴의 동작은 메서드로 분리합니다.

**검증 3종 (이 과제의 핵심)**

1. 입금/출금 금액이 0 이하면 거절하고 안내 메시지 출력
2. 출금 금액이 잔액보다 크면 거절
3. 없는 계좌번호로 입금/출금/조회하면 "존재하지 않는 계좌" 안내 (null 가드, 모듈 5)

## 스스로 검증 연습 (AI를 썼다면 필수, 직접 짰어도 권장)

완성한 코드에 대해 아래를 직접 수행하고, 코드 상단 주석에 "검증 노트"로 남겨보세요.

1. 깨뜨려보기: 음수 입금, 잔액 초과 출금, 없는 계좌 조회, 계좌 100개 초과 생성 등 경계를 최소 5가지 직접 입력해보고, 어떻게 동작했는지 기록
2. 발견한 문제 3가지: AI가 짰든 내가 짰든, 위 실험에서 발견해 고친 문제를 3가지 기록 (없다면 "발견 못 함"이 아니라 더 공격적인 입력을 찾아볼 것)
3. 설명 못 하는 줄 0개: 코드의 모든 줄을 "이 줄은 왜 필요한가"로 설명할 수 있는지 확인. 설명 못 하는 줄이 있다면 AI에게 물어서라도 이해하고 넘어가기

이 세 가지가 되면, AI가 짠 코드라도 여러분의 코드입니다. 안 되면, 직접 짠 코드라도 남의 코드입니다.

## 확장 아이디어 (시간이 남는다면)

- 계좌번호 자동 채번 (예: 1001부터 증가)
- 거래 내역 배열을 계좌마다 두고, 조회 시 최근 5건 출력
- 이체 기능 (출금 + 입금의 조합. 한쪽이 실패하면 어떻게 해야 할까요? 이 질문이 입과 후 배울 "트랜잭션"입니다)
